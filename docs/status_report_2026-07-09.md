## 1. 문제 정의 (제약·목표)

셔틀버스가 ∧자 분기점에서 회차한다: 아래 경사로로 진입 → 회차 → 윗 경사로로 진출.

- **차량 운동학** (bicycle model, 뒷축 기준): 축거 L=6.290m, 뒷축중심 회전반경
  R=7.37m(R_min 스펙 10.5m를 앞윤거 T_f=2.075m로 보정 역산), δ_max=40.5°,
  곡률한계 |κ|≤1/R=0.1357. 전/후진 v_max ±2.0m/s.
- **시작 자세** (뒷축): (-20.639, -10.261, 17.24°) — 아래 경사로 시작 캡 중앙.
- **목표 자세**: 버스 **앞면 중앙**이 윗 경사로 끝단 캡 중앙에 닿음
  (-28.197, 2.069, 168.25°), 허용오차 위치 0.5m·헤딩 0.1rad. **전진(FWD)으로
  도착**해야 함(후진 도착 무효) — 사용자 하드 요구.
- **최적화 목표**: 전후진 방향전환 횟수 최소화(1순위), 총거리·우회 최소화.

### 1-1. 현장 사실 (코드로 유추 불가, 사용자 확인)
- **노면 경계 = 포장 가장자리이며 연석(緣石)이 있다.** → **바퀴는 경계를 못
  넘지만, 차체 오버행(앞 2.77m/뒤 2.72m)은 연석 위 허공으로 넘어가도 된다.**
  이것이 §4의 핵심 근거.
- **아래 경사로(진입) = 일방통행.** → 진입 구간은 우측통행 불필요.
- **윗 경사로(진출) = 2차선 양방향.** → **진출 구간은 우측통행 필요**(§7).

## 3. 이전 경로(바디 모델)의 문제

직전 경로(`reference_path.json`, 403노드)는 **차체 전체(뒷축→앞범퍼 9.06m)** 를
경계 안에 가두는 충돌모델로 계획돼, 좁은 통로에서 잘게 26~28회 전후진해야 했다.

**결정적 진단(수치 검증):** 바퀴 외측 회전반경 10.5m vs 바디(범퍼) 외측 12.5m.
180° U턴 필요폭 = 바퀴 21.0m / 바디 25.0m. 개방 회차구역 실폭 = 21.9m.
→ **바퀴 모델이면 U턴이 들어가고(21.0<21.9), 바디 모델이면 안 들어가(25.0>21.9)
다점 K턴 강제.** 즉 26회 전환의 절대다수가 잘못된 충돌모델의 인공물.

## 7. 진행 중 — 우측통행 진출 (미확정)

### 7-1. 요구사항 (2026-07-09 명확화)
윗 경사로(진출)는 **2차선 양방향**이므로, 마지막 2차 후진 이후의 전진 진출
구간(run4)이 **오른쪽 차선(우측통행)** 으로 붙어야 한다. 아래 경사로(진입)는
일방통행이라 불필요. 회차(run0~3)는 그대로 둔다.

### 7-2. 객관적 현황
진출 구간(run4)은 현재 **좌측통행**임을 실측 확인: 진행방향 기준 평균 여유가
**왼쪽 3.71m << 오른쪽 6.68m**. 오른쪽에 6.7m 비어있는데 안 씀. → 오른쪽으로
약 1.5~2m 이동시키면 우측통행.

### 7-3. 시도와 실패
1. **Hybrid A*로 run4만 재계획 + 왼쪽 keep-out 띠**(`tests/replan_exit_keepright.py`):
   - keep-out 지오메트리 버그 2회 수정(200m 단측버퍼가 진입램프까지 삼킴 →
     국소 6m 띠+통로 클립으로 수정, 시작/목표 원 비움). keep-out 모양은 정상화됨
     (`outputs/keepright_dryrun.png`).
   - 그러나 **전진 트리가 348노드에서 죽음**(양방향 접합 실패). 원인: 속도를 위해
     거친 격자로 낮췄더니 **포켓 탈출부의 미세 기동을 못 만들어 트리가 조기 사멸**
     (fine 격자면 되지만 느림). closed_a=348이 설정 무관하게 동일 → keep-out이
     아니라 격자 해상도가 원인임을 확인.
2. **run4를 옆으로 미는 방식**(`tests/shift_exit_keepright.py`): 플래너를 안 쓰고
   이미 유효한 run4를 진행방향 오른쪽으로 offset 이동, 시작/목표는 taper로 0.
   - 1차(offset 2m 균일): **곡률 0.736(한계 0.136의 5.4배) 초과 + 바퀴위반 34**.
     원인: **곡선 구간(포켓 탈출)까지 밀어서** 꺾임 발생.
   - 개선: **곡선 구간은 안 밀고 직진 구간만**(원본 곡률로 직진도 가중) + 전이
     스무딩 + offset 1.5m. (이 개선판의 확정 검증은 미완.)

### 7-4. 현재 스크립트 상태 (주의)
`tests/replan_exit_keepright.py`, `tests/shift_exit_keepright.py`는 이후 **다른
도구/AI에 의해 추가 수정**된 상태다(예: shift 스크립트에 goal-pose morph,
`--goal-offset-right`, `--goal-heading-deg`, `--heading-mode`, `_fit_within_boundary`
등이 추가됨). 사용자가 그 결과에 만족하지 못해 재개를 요청함. **다음 작업 시
현재 파일 상태를 먼저 재확인하고, 옆이동 방식(곡선 보호+스무딩)을 기준으로
offset을 튜닝해 곡률≤0.136·바퀴위반 0을 만족시키는 것이 목표.**

### 7-5. 대안 (더 견고하지만 큰 작업)
`path_optimization_deep_plan_2026-07-08.md`의 Layer 2·3 — Reeds–Shepp 해석적
확장을 Hybrid A*에 추가(포켓 탈출·목표 도달을 깔끔히), 이후 다중슈팅 NLP(SLSQP)로
매끈화. 우측통행은 이 프레임에서 lane 비용/코리도어 타겟으로 자연스럽게 반영 가능.
