# 최종 채택 경로계획 알고리즘 명세서 — Hybrid A* (바퀴 충돌모델) 및 양방향 접합

- 작성일: 2026-07-09
- 대상: ∧자 분기점 셔틀버스 회차 경로 계획
- 핵심 구현: `simulation/planning/hybrid_astar.py`, `simulation/generate_rightbias_path.py`
- 최종 산출물: `simulation/geometry/reference_path_wheelmodel.json`(회차 골격),
  `simulation/geometry/reference_path_keepright.json`(우측통행 진출 반영본)

본 명세서는 채택 알고리즘의 제약 조건과 경로 생성 원리를 코드 근거와 함께 기술한다.
제4장(비용함수 튜닝 근거)과 제5장(양방향 접합 및 되감기 수학)은 심화 분석에 해당한다.

---

## 1. 개요

### a. 알고리즘 정의

채택 알고리즘은 뒷축 `(x, y, θ)` 상태공간에서 최소회전반경을 준수하는 전/후진 원호
프리미티브를 격자 상에 연결하여 최소비용 경로를 탐색하는 Hybrid A*이다. 충돌 판정은
차체(범퍼)가 아닌 바퀴 접지면을 기준으로 하며, 방향전환 및 후진에 비용 페널티를
부여하여 전후진 전환 최소화를 유도한다. 단방향 탐색이 좁은 포켓에서 실패할 경우
양방향 탐색을 수행한 뒤 두 트리를 접합하여 해를 완성한다.

### b. 알고리즘 선정 근거

기존 접근법 대비 채택 사유는 다음과 같다.

| 후보 | 결과 | 사유 |
|---|---|---|
| PPO(강화학습) | 폐기 | 좁은 회차 구간에서 성공률 붕괴 후 미회복 |
| CMA-ES(진화적 최적화) | 실패 | 단일슈팅 연쇄 민감성 및 미분 신호 부재로 좁은 헤어핀 통과 불가 |
| switch-repair(국소 후처리) | 부분 성공(28→26회) | 경로 골격 변경 불가 |
| Hybrid A* + 바퀴모델 | 채택(4회/62.6m) | 이산 전후진 조합 문제에 격자 탐색이 구조적으로 적합 |

본 문제는 연속 최적화로 좁은 벽 사이 진행방향 그래디언트를 확보하는 문제가 아니라,
이산적 전/후진 스위칭을 조합적으로 탐색하는 문제이다. 따라서 격자 기반 탐색(A* 계열)이
구조적으로 적합하다.

## 2. 제약 조건

### a. 차량 운동학 (kinematic bicycle model, 뒷축 기준)

- 축거 `L = 6.290 m`
- 최소회전반경(뒷축 중심) `R = 7.37 m`. 공표 스펙 `R_min = 10.5 m`(바깥 앞바퀴 자국
  기준)를 앞 윤거 `T_f = 2.075 m`로 역산 보정한 값이다.
- 최대 조향각 `δ_max = 40.5°`, 곡률 한계 `|κ| ≤ 1/R = 0.1357 m⁻¹`
- 각 프리미티브는 곡률이 일정한 원호이며, 조향은 이산 집합에서 선택한다.
  `δ = steer_frac × δ_max`, `steer_frac ∈ {−1.0, …, +1.0}`(미세 탐색 시 21개).
- 상태 전이는 전방 오일러 6분할로 계산한다
  ([hybrid_astar.py:86-98](../simulation/planning/hybrid_astar.py#L86-L98)).

  ```
  ds = arc_len / 6,  v_sign = +1(FWD) / −1(REV),  δ = steer_frac·δ_max
  6회 반복:
      θ ← θ + v_sign·(ds/L)·tan δ
      x ← x + v_sign·ds·cos θ      (위치는 갱신 전 θ 사용)
      y ← y + v_sign·ds·sin θ
  ```

  곡률은 `κ = tan(δ)/L`로 프리미티브 전 구간에서 일정하다. `δ_max`가 곡률 한계를
  자동으로 만족(`tan(δ_max)/L = 1/R`)하므로 별도 곡률 제약 검사는 불요하다.

### b. 충돌 판정 (바퀴 접지 기준)

- footprint = `(front = L = 6.29 m, rear = 0.0, half_width ≈ 1.2475 m)`
  (`generate_rightbias_path.py:28`)
- 현장 조건상 노면 경계는 연석(緣石)을 포함한 포장 가장자리이다. 바퀴는 경계를
  넘을 수 없으나(연석에 걸림) 차체 오버행(앞 2.77 m, 뒤 2.72 m)은 연석 상부 공간으로
  넘어갈 수 있다. 따라서 충돌 판정에서 오버행 제외가 물리적으로 타당하다.
- 각 프리미티브의 6개 세부점 전부에 대해, 뒷축 기준 OBB(footprint)가 경계 폴리곤에
  완전 포함(`boundary.contains(poly)`)되고 장애물과 교차하지 않음을 검사한다
  ([hybrid_astar.py:67-81](../simulation/planning/hybrid_astar.py#L67-L81),
  [212-217](../simulation/planning/hybrid_astar.py#L212-L217)).
- 대비: 초기 차체(범퍼) 모델은 `front_oh = d_ref = 9.06 m`, `rear_oh = 2.72 m`이며,
  이 과보수 모델이 다점 K턴을 강제하였다(제6장 참조).

### c. 시작 및 목표 자세

- 시작(뒷축): `(-20.639, -10.261, 17.24°)`. 아래 경사로 시작 캡 중앙.
- 목표: 버스 앞면 중앙이 윗 경사로 끝단 캡 중앙에 접함. `(-28.197, 2.069, 168.25°)`,
  허용오차 위치 0.5 m, 헤딩 0.1 rad. 플래너 내부 허용창은 tol_pos=0.6 m, tol_heading=12°.

### d. 도착 방향 제약 (전진 도착 전용)

- 후진으로 위치만 정합하는 도착은 무효로 처리하며, 앞면부터 전진(FWD)으로 도착해야 한다.
- 마지막 단일 에지만 FWD인지 검사할 경우 후진으로 목표를 지나친 뒤 소폭 전진으로
  복귀하는 도착이 통과되는 결함이 확인되었다(2026-07-04). 이에 `_fwd_run_length`로
  최근 N스텝(`arrival_min_fwd_run`, 기본 3) 연속 전진을 요구한다
  ([hybrid_astar.py:100-111](../simulation/planning/hybrid_astar.py#L100-L111),
  [184-202](../simulation/planning/hybrid_astar.py#L184-L202)).

### e. 비용함수 (최적화 목표)

프리미티브당 비용은 다음과 같이 산정한다
([hybrid_astar.py:219-224](../simulation/planning/hybrid_astar.py#L219-L224)). 세부
근거는 제4장에 기술한다.

```
step_cost  = arc_len                        # 기본: 이동 거리
if REV:    step_cost *= reverse_penalty      # 후진 억제 (≈1.3)
if 기어전환: step_cost += gear_switch_penalty   # 방향전환 억제 (3.0)
step_cost += 0.3 · |steer_frac|              # 급조향 완화 페널티
```

## 3. 알고리즘 원리

표준 A*를 연속 상태공간의 격자 이산화 형태로 구현한 Hybrid A*이다.

1. 노드는 뒷축 자세 `(x, y, θ)`와 기어(FWD/REV/START)로 정의한다. 연속 공간을 격자
   셀로 이산화(`_cell`, [hybrid_astar.py:83-84](../simulation/planning/hybrid_astar.py#L83-L84))하여
   동일 셀에 속하는 자세는 병합한다. 셀 해상도는 `(xy_res, theta_res)`이다.
2. 에지는 고정 길이 원호 프리미티브이다. 각 노드에서 `{FWD, REV} × {steer_fracs}`
   조합으로 확장하며, 프리미티브 전체가 충돌 없을 경우 자식 노드를 생성한다
   ([hybrid_astar.py:208-235](../simulation/planning/hybrid_astar.py#L208-L235)).
3. 우선순위는 `f = g + h`로 산정한다. `g`는 누적 비용(제2장 e), `h`는 목표까지의
   유클리드 거리에 헤딩차의 1.5배를 가산한 값이다
   ([hybrid_astar.py:373-377](../simulation/planning/hybrid_astar.py#L373-L377)).
4. 힙에서 `f` 최소 노드를 추출하여 확장한다. 목표 허용오차 내에 진입하고 도착 기어
   조건(제2장 d)을 동시 만족하면 종료한다
   ([hybrid_astar.py:169-202](../simulation/planning/hybrid_astar.py#L169-L202)).
   위치·방향은 정합하되 도착 기어 조건을 미충족하는 경우 종료하지 않고 확장을 지속한다.
5. 단방향(start→goal) 탐색이 예산 내에 실패하면 양방향 탐색 및 접합(제5장)으로 전환한다.

탐색 진단 트래커와 관련하여, `best_dpos`(위치 전용) 및 `best_combined`(위치+방향)는
기어 조건을 무시하는 참고용 지표이다. 트리 전체에서 도착조건 만족 노드의 최솟값을
취할 경우 목표와 무관한 지점이 선택되는 오진 사례가 확인되었다
([hybrid_astar.py:159-167](../simulation/planning/hybrid_astar.py#L159-L167)). 이에
허용오차의 `NEAR_MULT=4`배 이내이면서 도착조건도 만족하는 `near_valid_candidate`만을
근접 후보로 신뢰한다. 트리가 조기 사멸하더라도 이 지표로 실제 근접 여부를 먼저
확인해야 한다.

## 4. 비용함수 튜닝 근거 (심화)

비용함수의 각 항은 회피 대상을 거리 단위로 환산한 가중치이다. `arc_len`(프리미티브
1개 = 0.3 m 주행)을 기준 단위로 하면 각 페널티의 정량적 의미가 명확해진다.

### a. gear_switch_penalty = 3.0 (전후진 최소화의 정량 인코딩)

- 방향전환 1회 비용은 `3.0`이며, 프리미티브 1개가 `0.3`이므로 방향전환 1회는
  프리미티브 10개, 즉 약 3.0 m의 추가 주행과 등가이다.
- 해석: 플래너는 약 3 m 이내의 추가 우회를 감수하고 방향전환 1회를 제거한다.
  사용자가 전후진 횟수 최소화를 1순위로 지정하였으므로 본 값을 크게 설정하였다.
- 튜닝 이력: 초기값은 3.0이었으나, 해 탐색 자체가 실패하던 시기에 임시로 0.5까지
  하향하였다가 복원하지 않아 경로가 38회 전환의 과도한 지그재그 형태로 산출된 사례가
  있다. 원인 파악 후 3.0으로 복원하고 재실행한 결과 전환 38→28회, 길이 116.2→120.6 m로
  변화하였다. 즉 본 값이 "거리 소폭 증가 대 전환 대폭 감소"의 트레이드오프를 지배한다.

### b. reverse_penalty ≈ 1.3 (후진의 상대 비용)

- 후진 프리미티브는 전진 대비 거리당 30% 높은 비용을 갖는다(클래스 기본값 1.6,
  최종 실행 스크립트 `generate_rightbias_path.py:41`에서 1.3 적용).
- 목적은 불필요한 후진 억제와, 포켓 탈출용 K턴 등 필수 후진 기동의 보존을 양립하는
  것이다. 값이 과대하면 필수 후진 기동을 생성하지 못해 트리가 사멸하고, 과소하면
  전후진이 빈발한다. 1.1~1.6 범위 조정 결과 1.3을 채택하였다.

### c. 급조향 페널티 +0.3·|steer_frac| (부드러움 선호)

- 직진(sf=0)은 0, 최대조향(|sf|=1)은 `0.3`을 가산한다.
- 목적은 동일 비용 시 조향량이 적은 경로를 선택하여 곡률 부호 전환과 요동을 억제하는
  것이다. 가중치가 방향전환 페널티(3.0) 대비 작아 필요한 조향 자체는 제약하지 않는다.

### d. 휴리스틱 가중치 h = dist + 1.5·Δheading (탐색 속도 대 최적성)

- 헤딩차(rad)에 1.5를 곱하여 위치는 정합하나 방향이 어긋난 노드의 우선순위를 낮춘다.
- 본 계수는 순수 admissible 하한이 아니라 탐색 가속을 위한 완화(weighted A* 성격)이다.
  최단성 보장을 일부 희생하는 대신 목표 지향성을 높여 좁은 문제에서 탐색을 실용화한다.
  회차 문제는 헤딩 정렬이 병목이므로 본 가중이 효과적이다.

### e. 도착 판정 파라미터

- `tol_pos = 0.6 m`, `tol_heading = 12°`: 격자·프리미티브 이산화 오차를 흡수하는
  도착 창이다. 목표 스펙(0.5 m, 0.1 rad)보다 다소 느슨하나 도착 후 정밀 검증으로
  보정한다.
- `arrival_min_fwd_run = 3`: 제2장 (d)의 도착 방향 제약을 위한 값으로, 최근 3스텝(약 0.9 m)
  연속 전진을 요구한다.
- `NEAR_MULT = 4.0`: 진단 전용. 근접 후보 인정 범위를 허용오차의 4배로 제한한다.

### f. 파라미터 요약

| 파라미터 | 최종값 | 역할 | 조정 방향의 함의 |
|---|---|---|---|
| `gear_switch_penalty` | 3.0 | 방향전환 억제 | 상향 시 전환↓·거리↑, 하향 시 지그재그 |
| `reverse_penalty` | 1.3 | 후진 억제 | 상향 시 후진↓(과대 시 트리 사멸) |
| 급조향 페널티 | 0.3·\|sf\| | 부드러움 | 상향 시 완만·직진 선호 |
| `h` 헤딩 가중 | 1.5 | 탐색 가속 | 상향 시 속도↑·최적성↓ |
| `arc_len` | 0.3 m | 프리미티브 길이 | 하향 시 미세기동 표현·속도↓ |
| `xy_res / theta_res` | 0.2 m / 2° | 셀 해상도 | 하향 시 표현력↑·분기↑·속도↓ |
| `steer_fracs` | 21개 | 조향 이산화 | 상향 시 매끄러움·속도↓ |
| `tol_pos / tol_heading` | 0.6 m / 12° | 도착 창 | 이산화 오차 흡수 |
| `arrival_min_fwd_run` | 3 | 전진도착 강제 | 무효 도착 차단 |

## 5. 양방향 탐색·접합·되감기 수학 (심화)

### a. 양방향 탐색의 필요성

목표(윗 경사로 캡)는 좁은 포켓 안쪽에 위치하여, start에서 단방향으로 확장하는 트리가
포켓 입구에서 예산을 소진하고 사멸하는 경향이 있다. 이에 goal을 루트로 하는 제2 트리를
동시에 확장하고, 두 트리의 접점에서 경로를 연결한다
([hybrid_astar.py:298-327](../simulation/planning/hybrid_astar.py#L298-L327)).

### b. 폐기된 좌표 반사 트릭 및 결함

초기 구현은 goal의 heading을 180° 반전하여 동일 전진 탐색으로 역방향 트리를 생성하는
반사(reflection) 트릭을 사용하였다. 본 차량은 뒷축 기준 전/후 오버행이 비대칭(9.06 m
대 2.72 m)이므로, heading을 180° 반전하면 충돌검사에 사용하는 차체 형상이 전혀 다른
형태로 변형되어 충돌 판정이 무의미해지는 결함이 발생하였다. 이에 반사 방식을 폐기하고
좌표 변환 없이 goal을 루트로 실공간 탐색을 수행한다.

### c. 되감기(`_reverse_chain`)의 수학적 근거

되감기는 경로를 재적분하지 않는다. goal 트리에서 산출·저장된 자세 열
`(x_i, y_i, θ_i)`의 순서를 반전하고 기어 라벨만 FWD↔REV로 교체한다
([hybrid_astar.py:348-362](../simulation/planning/hybrid_astar.py#L348-L362)).

```
chain(root→node):  P0 —g1→ P1 —g2→ P2 … —gn→ Pn      (gi = 에지 i의 기어)
reversed        :  Pn —g'n→ … P2 —g'2→ P1 —g'1→ P0    (g'i = REV if gi==FWD else FWD)
                   (Pn은 새 START, 위치·헤딩은 원본 유지)
```

정확성의 근거는 원호의 가역성이다. 자전거 모델에서 각 프리미티브는 곡률
`κ = tanδ/L`가 일정한 원호이다. 전진(`v_sign=+1`)으로 `A→B`를 주행한 호를 `B→A`로
되짚는 운동은 동일 조향 `δ`의 후진(`v_sign=−1`)이다. 상태 전이식에서 전진 A→B는
`Δθ = +κ·ds`이고, 후진 B→A는 `Δθ = −κ·ds`로 헤딩이 정확히 역으로 감기며 위치도
헤딩 반대 방향으로 후퇴하므로, A→B에서 경유한 점들을 역순으로 정확히 되짚는다.
곡률이 동일하고 진행 부호만 반대이므로 좌표 반사가 불요하다. 또한 코드가 저장된
`(x_i, y_i, θ_i)`를 그대로 재사용하므로 오일러 이산화 오차가 추가로 유입되지 않으며,
되짚는 점들이 원본과 완전히 동일하다. 기어 교체는 해당 호를 반대 방향으로 주행함을
나타내는 의미 라벨링에 해당한다.

### d. 접합(`_splice_bidirectional`) 및 접합부 불연속

두 트리가 동일 격자 셀에서 접하면, 트리 A는 `start→meet_a`, 트리 B는 `goal→meet_b`
경로를 확보한 것이다. B를 되감아 연결하면 전체 경로가 완성된다
([hybrid_astar.py:329-371](../simulation/planning/hybrid_astar.py#L329-L371)).

```
전체 = reconstruct(meet_a)                      # start … meet_a
     + reverse_chain(reconstruct(meet_b))[1:]   # meet_b … goal (meet_b 제외)
```

복수의 접합 후보 중에서는 `g(meet_a) + g(meet_b)`가 최소인 쌍을 선택한다
(`_find_meeting`, [hybrid_astar.py:329-346](../simulation/planning/hybrid_astar.py#L329-L346)).

접합부 불연속에 관하여, `meet_a`와 `meet_b`는 동일 셀에 속할 뿐 동일 자세가 아니다.
따라서 접합점에서 최대 `xy_res`(0.2 m), `theta_res`(2°) 규모의 위치·헤딩 불연속이
존재할 수 있다. `reverse_chain`이 `meet_b`를 제외(`[1:]`)하여 중복은 제거하나 격자
규모의 kink는 잔존한다. 본 오차는 도착·충돌 전수 재검증(바퀴 위반 0)과 후속 스무딩으로
흡수되며 셀 해상도로 상한이 규정된다. 완전 연속 경로가 요구될 경우 해당 지점에 국소
스무딩 또는 Reeds–Shepp 해석적 연결을 적용함이 타당하다.

## 6. 결과 및 형상 타당성

### a. 정량 성과 (`reference_path_wheelmodel.json`, 209노드)

- 방향전환 4회(이전 26~28회), 총 길이 62.6 m(이전 120.6 m, −48%)
- 바퀴 경계위반 0(209노드 전수 검증)
- 구간 구조: 전진(진입→포켓) → 후진 → 소폭 전진 → 후진 → 전진(진출)
- 범퍼가 연석을 넘는 노드 93/209개. 바퀴 모델이 허용한 여유이며 구모델이 오차단한 영역이다.

### b. 바퀴 모델의 형상 결정 근거

| 항목 | 바퀴 모델 | 차체(범퍼) 모델 |
|---|---|---|
| 외측 회전반경 | 10.5 m | 12.5 m |
| 180° U턴 필요폭 | 21.0 m | 25.0 m |
| 개방 회차구역 실폭 | 21.9 m | 21.9 m |
| 넓은 U턴 성립 여부 | 성립(21.0 < 21.9) | 불가(25.0 > 21.9), 다점 K턴 강제 |

이전 26~28회 전환의 대부분은 과보수 충돌모델에 기인한 인공물이며, 연석 상부 오버행
허용이라는 현장 조건을 반영하자 전환이 4회로 감소하였다.

### c. 우측통행 진출 후처리 (`reference_path_keepright.json`)

회차 골격(마지막 후진까지)은 유지하고 마지막 전진 진출 구간만 재설계한다. 진출 각
지점에서 좌·우 벽까지 ray를 투사하여 도로폭을 측정하고, 오른쪽 차선 중앙(좌측벽 기준
폭의 3/4 지점)을 목표 가로위치로 산정한다. 시작점(헤딩 연속)에서 램프 1/3 지점의 오른쪽
차선까지를 Hermite 곡선으로 합류시킨 뒤 라플라시안 스무딩을 적용하고, 곡률(≤1/R) 및
바퀴 위반을 재검증한다. 윗 경사로가 2차선 양방향이므로 우측통행이 필요하며, 아래
경사로는 일방통행이므로 진입 구간에는 적용하지 않는다.

## 7. 한계 및 향후 과제

1. 접합부 미세 불연속(제5장 d): 격자 규모(0.2 m, 2°) 상한의 kink가 잔존한다. 해석적
   연결(Reeds–Shepp) 또는 국소 스무딩으로 제거 가능하다.
2. 해석적 목표 연결 부재: 본 플래너는 목표 근방에서 격자를 탐색하며 미세 격자 및
   양방향 접합에 의존한다(약 41분 소요). Reeds–Shepp 골 확장 적용 시 cusp 최소성이
   구조적으로 보장되고 속도가 개선된다.
3. 바퀴 충돌모델의 공유 코드 미반영: 현재 실행 스크립트에만 적용되어 있다. 공유
   모듈(`bus_hairpin_env.py`, `hybrid_astar.py`)에 정식 반영이 필요하다.
4. 제원 실측치 미확보: `R_min = 10.5 m`, `T_f = 2.075 m`는 추정치이며, 실측 확보 시
   폭·회전반경 모델을 정밀화해야 한다.
5. 우측통행 진출 최종 확정 미완: 곡률·바퀴위반을 모두 통과하는 offset 확정 후
   DXF 및 구역 이미지 재생성이 필요하다.
