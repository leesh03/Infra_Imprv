## 1. 목표와 배경

셔틀버스가 좁은 ∧(역V)자 분기점에서 회전반경 부족으로 한 번에 돌지 못하고 전·후진을 여러 번 반복한다. 이 프로젝트는 **설계 단계에서만** AI를 사용한다 — 학습 결과는 정적 노면 마킹으로 출력되고, 실제 운영 중에는 센서·AI가 개입하지 않는 **오프라인 경로 최적화** 문제다.

운동학은 **Kinematic Bicycle Model**(질량·마찰 제외 순수 기구학)을 사용하고, 도로의 종단 경사(윗 갈래 1.97% / 아랫 갈래 8.24%, 정점에서 전환)가 문제의 핵심 변수다 — 전·후진 방향전환이 경사가 꺾이는 지점에 몰리는 것이 실제 위험 패턴으로 확인되었다.

**최종 산출물**
- `bus_hairpin_policy.zip` — 학습된 PPO 정책
- `optimal_path.csv` — 최적 회차 경로 좌표
- `steer_points.csv` — 조향 전환점(마킹 지점)
- `road_marking_design.dxf` — 노면 마킹 설계 도면
- `reward_curve.png` — 학습 곡선

## 3. 환경 설계 요약

기준점을 **둘로 분리**한 것이 설계의 핵심 결정이다 — 운동학 적분은 **뒷축 중심**, 목표 도달 판정은 **앞면 하단 중심**(`d_ref = 9.0623m`)을 사용한다. 두 기준을 섞으면 회전 거동이 틀어지므로 전 모듈에서 강제된 규칙이다.

### 버스 제원
| 항목 | 값 |
|---|---|
| 전장 | 11.780 m |
| 전폭 | 2.495 m |
| 축거 (L) | 6.290 m |
| 전방/후방 오버행 | 2.772 / 2.718 m |
| d_ref (뒷축 → 앞면) | 9.0623 m |

### 운동학 / 시뮬 파라미터
| 항목 | 값 |
|---|---|
| v_max / v_min | ±2.0 m/s |
| a_max | 1.0 m/s² |
| dt | 0.1 s |
| δ_max | atan(L / R_min) |
| 경사 (윗/아랫) | 1.97% / 8.24% |

### Observation (연속)
- 목표 상대자세 Δx, Δy, Δθ (버스 좌표계, 앞면중심 기준)
- 현재 v, δ
- 경계 여유 레이 센서 (n_rays 방향)
- 현재 경사 `grade_at` + 전방 lookahead `grade_ahead`
- 참조경로 진행률 `progress_fraction` + 횡오프셋 `lateral_offset`

### Action / 종료조건
- `Box[-1,1]²` → (a_accel, a_steer) 내부 스케일링
- 충돌: 뒷축 포즈 기준 OBB가 도로 폴리곤/장애물과 교차 시 종료
- 성공: `front_center`가 tol_pos 0.5m · tol_heading 0.1rad · |v|<0.1 이내
- `max_episode_steps` 도달 시 truncate

### 보상 함수
| 보상 항 | 형태 | 의도 |
|---|---|---|
| 진행률 shaping | `w_pose·(prev_metric − curr_metric)` | potential-based — 절대거리 페널티가 "빨리 충돌해 끝내는" 퇴화 정책을 유리하게 만든 1차 실패 이후 재설계 |
| 목표 도달 보너스 | `+goal_bonus` (success 시) | 성공 정의 |
| 경계 여유 | `−w_clear·(threshold − clearance)` | 안전 마진 확보 |
| 급조향 페널티 | `−w_steer_smooth·|Δδ|` | 매끄러운 궤적 |
| 방향전환 페널티 (경사비례) | `−w_reversal·(1+k·grade)` | 가파른 구간 전후진 셔플 회피 |
| 정지체류 페널티 (경사비례) | `−w_stop_slope·grade` (저속시) | 경사에서 멈칫거림 회피 |
| 충돌 | `−collision_penalty`, 종료 | 통과불가 구간 차단 |

## 4. 진행 타임라인

**1차 학습 (구 도면, v6 3분리 도면 기준)** — PPO 베이스라인 학습 완료(`bus_hairpin_policy.zip`).
첫 시도에서 `ep_len_mean≈13`, 성공률 0%로 수렴하는 퇴화 정책 발견 → 원인은 절대거리 페널티가 충돌 페널티보다 쉽게 누적되는 보상 설계 결함. Potential-based shaping으로 보상 재설계 후 재학습.

**3M steps, ramp_fraction=0.6** — 커리큘럼 학습 중 성공률 붕괴 확인.
쉬운 구간에서는 성공률 100%까지 상승했으나, 난이도가 실제 START까지 차오르는 시점(1.8M step)에서 성공률이 0%로 무너진 뒤 회복하지 못함 — 정책이 정지 행동(action≈0)에 갇혀 여유 공간을 소진하고 충돌. `ramp_fraction 0.6→0.85`, `total_timesteps 3M→5M`로 조정.

**2026-07-02** — `road_model.dxf`가 v3(통합 도면)로 교체됨.
3개로 나뉘어 있던 도면이 하나로 통합되면서 레이어 이름·경계 형상이 변경. TASK1–3(파싱/폴리곤/경사장) 재작업 완료 — 헤어핀 형상, 아랫 갈래(급경사 8.24%)와 윗 갈래(완경사 1.97%)가 만나 좁은 "훅" 노치(폭 ~4.3m)를 이루는 형태로 확정. 전체 버스 OBB 기준 충돌 없는 새 시작/목표 포즈도 확정.

**진행 중** — 신규 지오메트리용 회차 참조경로(`reference_path.json`) 미확정, **현재 블로커**.
수동 컨트롤러(pure-pursuit + K턴)와 기하학적 원호 구성 모두 훅 노치에서 회전의 55–80% 지점을 넘지 못함. Hybrid A* 플래너를 새로 구현해 탐색 중이나 목표 근처에서 위치는 근접해도 방향(heading) 조건을 동시에 만족하는 노드를 찾지 못하는 상태.

## 5. 현재 블로커

> **신규 지오메트리(v3 도면) 기준 회차 경로가 아직 확정되지 않아 TASK 8 재학습을 시작하지 못했다.**
> 현재 저장된 `bus_hairpin_policy.zip`은 교체 전(v6 3분리 도면) 도로 형상 기준 정책이며, 신규 도면에는 적용할 수 없다.

Hybrid A*(`simulation/planning/hybrid_astar.py`)는 목표 위치 0.2–0.3m 이내까지는 도달하지만 목표 방향(heading) 조건을 동시에 만족하는 노드를 찾지 못한 채 약 2,000–2,400개의 그리드 셀만 탐색하고 종료된다. 이 탐색 셀 수가 비정상적으로 적어, 실제 기하학적 불가능(진짜 막다른 길)인지 해상도/프리미티브 설정 문제인지 아직 구분되지 않은 상태다 — 진단용 "최근접 후보" 추적기가 위치만 보고 방향은 무시하는 결함이 있어 우선 수정이 필요하다.
