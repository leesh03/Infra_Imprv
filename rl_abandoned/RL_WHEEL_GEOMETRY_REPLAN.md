## 0. 먼저 — 무엇을 바꾸고, 무엇을 바꾸지 않는가

지금 파이프라인은 Kinematic Bicycle Model의 단일 조향각 δ로 뒷축을 적분하고, 충돌을 뒷축 기준 OBB로 판정한다. 여기서 정직하게 구분해야 할 사실이 하나 있다.

**바이시클 모델을 "앞바퀴 2개(애커먼) 모델"로 교체할 필요는 없다.** 대상 차량(현대 유니버스 엘레강스)은 2축 차량으로 앞축만 조향하고 뒷축은 조향하지 않는다. 그리고 애커먼 2륜을 명시적으로 모델링해도 **뒷축 중심의 궤적과 차체 자세(pose)는 단일 δ 바이시클 모델과 수학적으로 완전히 동일하다.** 따라서 2륜 모델로의 교체는 정확도를 높이지 못하는 "가짜 정교함"이며, 프로젝트의 정직성 기준에 어긋난다.

바퀴 기하가 **실제로 결과를 바꾸는 지점은 두 곳뿐이다.**

1. **R_min → δ_max 변환의 오류 (제약값 문제).** 공표 최소회전반경은 통상 *바깥 앞바퀴 자국* 기준으로 정의되는데, 바이시클 모델의 회전반경 R은 *뒷축 중심* 기준이다. 윤거(track)와 축거를 무시하고 `δ_max = atan(L / R_min)`으로 잡으면 조향 한계가 틀어진다.
2. **스윕 포락선 = 차체 모서리 궤적 (충돌 기하 문제).** 선회 중 실제로 쓸고 가는 영역의 *바깥 경계*는 앞 오버행 바깥 모서리(swing-out)가, *안쪽 경계*는 뒤 안쪽 모서리(off-tracking)가 결정한다. 중심선·점 기반 판정은 이를 놓친다.

→ **결론: "바퀴 고려"는 바이시클 코어를 재작성하는 것이 아니라, (a) 제약값 변환 재유도와 (b) 풋프린트 포락선 기반 충돌 판정으로 들어온다.** 이 계획의 PHASE 1·2가 각각 여기에 대응한다.

## PHASE 1 — 조향 제약(δ_max) 재유도 · TASK 4 수정

> 목적: 공표 R_min을 바이시클 모델의 δ_max로 **올바르게** 변환한다. 현재 `δ_max = atan(L / R_min)`은 R_min의 측정 기준을 무시하고 있어 오류일 가능성이 크다.

### 왜 바꾸는가 (현재 블로커와의 직접 연관)
현재 `atan(L / R_min)`은 R_min을 **뒷축 중심 반경**으로 가정한다. 그러나 공표 R_min이 **바깥 앞바퀴 자국 반경**(R_spec)이라면, 뒷축 중심 반경 R은 이보다 작다. 즉 실제 차량은 지금 모델이 허용하는 것보다 **더 크게 꺾을 수 있다.** 결과적으로 현재 δ_max는 **과소평가(과잉 보수)**되어 있고, 이것이 **훅 노치에서 경로를 못 찾는 현재 블로커의 원인일 수 있다** — 실제로는 통과 가능한데 조향 한계를 너무 좁게 걸어 불가능하게 만들었을 가능성.

### 올바른 변환식 (측정 기준별)
표기: L=축거, T_f=앞 윤거, W=전폭, R=뒷축 중심 반경(바이시클 모델 값), f_oh=전방 오버행.

- R_spec 이 **바깥 앞바퀴 자국 반경**인 경우:
  ```
  R = sqrt(R_spec² − L²) − T_f/2
  δ_max = atan(L / R)
  ```
- R_spec 이 **차체 최외곽(front outer corner, wall-to-wall) 반경**인 경우:
  ```
  R = sqrt(R_spec² − (L + f_oh)²) − W/2
  δ_max = atan(L / R)
  ```

두 경우 모두 결과 δ_max는 현재의 `atan(L/R_spec)`보다 **크다**(조향 여유가 늘어난다).

### 변경 항목
1. TASK 4의 `δ_max` 계산을 위 측정 기준별 식으로 교체.
2. 액션 클리핑(`a_steer → δ`)의 상한을 새 δ_max로 갱신.
3. **민감도 분석 스크립트** 추가: R_spec 측정 기준이 불확실할 경우 두 식의 δ_max를 모두 계산해, 어느 쪽이든 훅 노치 통과 가능성에 주는 영향을 비교.

### 완료 판정
- [x] δ_max가 R_min 측정 기준에 맞는 식으로 유도됨 (`kinematics/bicycle.py`의 `corrected_rear_axle_radius`/`delta_max_from_Rmin_spec`, `BicycleModel`이 반영)
- [x] 이전 δ_max 대비 값 변화량 및 그로 인한 통과 가능성 변화가 문서화됨 (`tests/delta_max_sensitivity.py` — outer_front_tire_track 기준 30.92°→40.48°(+9.56°), outer_body 기준 →57.18°(+26.26°))

## PHASE 2 — 충돌 기하 업그레이드 (스윕 포락선) · TASK 5 수정

> 목적: 충돌 판정을 "뒷축 기준 단순 OBB"에서 **오버행을 포함한 실제 차체 풋프린트의 스윕 밴드**로 끌어올린다. 이것이 앞 오버행 swing-out과 뒤 off-tracking을 흡수하는 핵심 장치다.

### 왜 바꾸는가
2D 점/단순 OBB 판정이 놓치는 두 효과:
- **전방 오버행 swing-out**: 전방 오버행 2.772 m 때문에, 급회전 시 앞 바깥 모서리는 바깥 앞바퀴보다 더 바깥으로 휘둘려 나간다.
- **후방 off-tracking**: 뒷바퀴가 앞바퀴보다 안쪽으로 파고들고, 뒤 안쪽 모서리가 회전 안쪽 경계를 결정한다.

이 둘의 합으로, 회전 중 실제 쓸어가는 폭은 전폭 2.495 m보다 훨씬 넓다.

### 변경 항목
1. **풋프린트 폴리곤화.** 차체를 (전장·전폭·오버행 반영) 4~8각형 폴리곤으로 정의하고, 매 스텝 뒷축 자세로부터 폴리곤을 world 좌표로 변환해 도로 경계 폴리곤과 교차 검사. (기존 OBB → 오버행 포함 실측 폴리곤)
2. **스윕 밴드 서브샘플링.** dt=0.1 s, v=2 m/s면 스텝당 0.2 m 이동으로 그 사이 모서리가 쓸고 지날 수 있다. 스텝 사이 자세를 K회(예: 3~5회) 보간해 폴리곤을 추가 검사 → "쓸어간 띠(swept band)" 근사.
3. **(검증용) 모서리 반경 대조.** 대표 최급 회전 자세에서 아래 이론 반경을 계산해 폴리곤 판정과 대조:
   - 바깥 스윕 반경(앞 바깥 모서리): `R_out = sqrt((R + W/2)² + (L + f_oh)²)`
   - 안쪽 스윕 반경(뒤 안쪽 모서리): `R_in ≈ R − W/2`
   - 스윕 폭(환형): `R_out − R_in` (이 값이 전폭보다 얼마나 넓은지가 곧 놓치고 있던 여유)

### 완료 판정
- [x] 충돌 판정이 오버행 포함 폴리곤 + 서브샘플링 기반으로 동작 (`bus_hairpin_env.py`의 `_check_collision(state, prev_state)`가 `collision_substeps`회 보간 검사, `_clearance`가 차체 4모서리+앞면중심 5점 기준으로 확장)
- [x] 대표 회전에서 폴리곤 스윕 폭이 이론 `R_out − R_in`과 일치(오차 허용범위 내) (`tests/verify_swept_envelope.py` — R_out 오차 4mm, R_in 오차 0mm, 스윕 폭이 전폭보다 +3.888m 넓음을 확인)

## PHASE 3 — 보상 함수 재보정 · TASK 7 수정

> 목적: PHASE 2로 clearance 정의가 바뀌었으므로, 이에 의존하는 보상 항을 재보정한다. (보상 구조 자체는 유지 — potential-based shaping + 경사비례 페널티는 이전 설계 그대로.)

### 변경 항목
1. **clearance 재정의.** 경계 여유 보상의 clearance를 "기준점→경계"가 아니라 **"스윕 폴리곤→경계"**의 최소거리로 교체. (이 항의 의미가 PHASE 2에서 실질적으로 달라진다.)
2. **안전 인플레이션 Δ 캘리브레이션.** 감으로 찍지 말고, 대표 회차 동작 몇 개에서 2D 폴리곤 여유 vs Vehicle Tracking swept 여유의 격차를 측정해 `Δ = 관측 최대 격차 + 마진`으로 확정. 학습 시 경계를 Δ만큼 안쪽으로 인플레이션.
3. **급조향 페널티 재점검.** δ_max가 PHASE 1에서 커졌으므로, `w_steer_smooth` 가중치가 상대적으로 과하지 않은지 재확인(조향 여유가 늘면 셔플이 줄 수 있어 재튜닝 여지).

- [ ] Δ가 측정 기반으로 확정되고 그 근거가 기록됨 — `boundary_margin_m: 0.0` 자리만 마련, PHASE 5(Vehicle Tracking 확보) 전까지는 미확정 상태로 남겨둠

3. 필요 시 Reeds-Shepp 거리 휴리스틱 도입 / 양방향 탐색 / 수동 발견 부분 K턴을 탐색 시드로 활용.
4. 경로 확정 후 `reference_path.json` 갱신(전진/후진 구간 색상 구분 포함).
5. 준비된 커리큘럼(`ramp_fraction=0.85`, `5M steps`)을 **수정된 환경**에 적용해 재학습.

### 완료 판정
- [ ] heading 조건까지 만족하는 참조경로 확정 또는 "기하학적 불가"로 판정 — **미해결.** 진단기 수정(1) 및 새 delta_max 반영 재탐색(2)까지는 완료했으나, 재탐색 결과 best_dpos 노드가 위치 0.345m까지 근접하고도 heading이 178.5° 어긋나 있고(사실상 반대 방향), 400,000 반복 예산 중 4,911회·닫힌 셀 1,966개에서 탐색공간이 소진됨(예산 부족이 아니라 도달 가능한 상태 자체가 고갈됨) — 근접 실패라기보다 현재 프리미티브 집합으로는 도달 불가에 가까운 신호. Reeds-Shepp 휴리스티/양방향 탐색/수동 K턴 시드(3)는 다음 세션으로 이월.
- [ ] 수정 환경에서 보상 곡선 상승 및 성공률 회복 확인 — 참조경로 미확정으로 재학습 미착수. `train_ppo.py`는 PHASE 1~3 반영 환경과 그대로 호환되므로 경로 확정 즉시 실행 가능.

## 부록 B — 선행 연구 / 참고 근거

이번 재설계는 팀이 개념설계 단계에서 조사한 선행 사례 4축 위에 있으며, 바퀴 기하 관련 부분은 아래 표준 방법론에 근거한다.

**팀 선행 조사 4축 (개념설계 기초조사)**
1. Swept Path 차량 회전궤적 분석 — 오프라인 검증 레이어(Vehicle Tracking)의 산업 표준 근거. PHASE 2·5가 이에 직접 대응.
2. 강화학습 기반 저속 정밀 기동 계획 — AI 핵심 레이어 근거. 전체 파이프라인의 학습 층.
3. 스마트 주차 점유 인식(CV) — 현재 범위(길 A) 미포함, 확장(길 B) 근거.
4. 주차보조·운전자 가이드 시각화 — 출력 형태(노면 마킹)의 근거.

**바퀴 기하 재설계의 표준 방법론 근거 (도메인 정설)**
- **Ackermann steering geometry** — 앞축 안쪽/바깥쪽 바퀴 각도 차이와 조향 기하의 고전 이론. PHASE 1의 R_min↔δ_max 변환의 기반.
- **Reeds & Shepp (1990), "Optimal paths for a car that goes both forwards and backwards"** — 전·후진 모두 가능한 차량의 최소 경로 곡선. baseline·warm-start(PHASE 4)의 근거.
- **Dolgov, Thrun, Montemerlo, Diebel — Hybrid A\* (반구조화 환경 자율주행 경로계획, DARPA Urban Challenge 계열)** — 비홀로노믹 제약을 반영한 격자 탐색. 현재 `hybrid_astar.py` 구현의 근거.
- **AASHTO 설계차량 회전 템플릿 / swept-path 분석** — 도로·교차로 설계에서 대형차 회전궤적 검증의 표준. Vehicle Tracking 검증의 이론적 배경.

> 참고: 위 4개 방법론은 해당 도메인의 정설(canonical) 문헌으로, 발표·보고서에 인용할 때는 정확한 서지사항을 원문에서 재확인할 것. 팀 4축 선행조사의 구체 사례 목록은 개념설계 발표자료를 그대로 승계하면 된다.
